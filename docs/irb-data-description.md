# Usage data description for IRB review

Generated by `tools/sync_release_files.py` from `src/analytics_schema.py` and `site_config.json`. Edit those files, not this one.

## Purpose

The study improves the practice questions of a study site for radiation oncology residents and describes how the site is used. When usage counts are on, the site records anonymous events about the questions answered and the pages used. The resident survey is separate, and the usage data are not linked to it. Only the study team sees the data. The site shows no difficulty labels and no results from other learners.

## Events and properties

The site sends the events below and nothing else. A property that is not listed is dropped, and an event is not sent if a listed property is missing or its value does not fit its description.

| Event | Sent when | Property | Values | Meaning |
|---|---|---|---|---|
| `view` | A page of the site was opened. | `route` | page address, lower case letters, digits, / _ - | The page address after the #, with card and slide numbers left out. |
| `ans` | A question was answered. | `item` | topic:number:hash, for example pdd:12:3fa9c1 | The question: the topic, the number of the question within the topic, and the first six characters of a hash of the question text. A question that is edited gets a new identifier. |
|  |  | `kind` | mc, multi, typed, sort, match, rank, fig | The form of the question: multiple choice with one answer, select all that apply, typed number, sort or true or false, match, rank, or tap the figure. |
|  |  | `ok` | true or false | Whether the answer was correct. |
|  |  | `attempt` | 1, 2, 3 | 1 for the first answer to this question, 2 for the second, 3 for the third or later. Counted from the answers stored in this browser. |
|  |  | `choice` | a letter or letters, a number, or two numbers from 0 to 100 separated by a comma | What was chosen. Multiple choice: the letter. Select all that apply: the letters in alphabetical order. Typed number: the value rounded to 3 significant digits. Sort, match, rank, and true or false: a number whose binary digits mark the items that were placed correctly. Tap the figure: the position of the tap as a percentage of each axis, rounded to the nearest 2. |
|  |  | `secs` | lt5, 5-15, 15-30, 30-60, gt60 | How long the question was in view before it was answered, in a coarse range: under 5 s, 5 to 15 s, 15 to 30 s, 30 to 60 s, or over 60 s. |
|  |  | `help` | true or false | Whether Explain further was opened for this question since the previous answer. |
| `more_q` | Explain further was opened under a question. | `item` | topic:number:hash, for example pdd:12:3fa9c1 | The question, identified as above. |
|  |  | `state` | before_answer, after_wrong, after_correct | Whether the question had not been answered, had been answered wrongly, or had been answered correctly. |
| `more_s` | Show more details was opened in a chapter. | `topic` | chapter identifier | Chapter identifier. |
|  |  | `section` | whole number | Section number within that chapter. |
| `card` | A flash card was shown. | `card` | topic:number | The card: the topic and the number of the card. |
|  |  | `action` | seen | The action. A card counts as seen when it is shown. |
| `mu` | A monitor-unit practice case was used. | `case` | whole number, or r | The case number, or r for a random case. |
|  |  | `action` | tried, solution | Whether the answers were checked or the solution was shown. |
| `about` | The About page was opened. | none | | |

## Example payloads

The examples use the example values in the schema.

### Collector run by the study team

Each event is an HTTP POST whose body is JSON, with no cookie and no referrer.

```json
{"event": "view", "props": {"route": "t/pdd/c"}}
{"event": "ans", "props": {"item": "pdd:12:3fa9c1", "kind": "mc", "ok": false, "attempt": 1, "choice": "B", "secs": "15-30", "help": false}}
{"event": "more_q", "props": {"item": "pdd:12:3fa9c1", "state": "after_wrong"}}
{"event": "more_s", "props": {"topic": "pdd", "section": "3"}}
{"event": "card", "props": {"card": "pdd:4", "action": "seen"}}
{"event": "mu", "props": {"case": "7", "action": "tried"}}
{"event": "about", "props": {}}
```

### GoatCounter

Each event is one request to the GoatCounter site. The request carries a path that encodes the event and a flag that marks it as an event. It carries no referrer, screen size, or page title.

```
ev/view/t/pdd/c
ev/ans/pdd:12:3fa9c1/mc/w/1/B/15-30/0
ev/more_q/pdd:12:3fa9c1/after_wrong
ev/more_s/pdd/3
ev/card/pdd:4/seen
ev/mu/7/tried
ev/about
```

## What is not collected

- Names
- Email addresses
- Accounts
- Times or dates from the device
- Cookies
- Identifiers stored in the browser
- Typed text of any kind other than the rounded number in the choice of a typed-number question
- The text of any free-text field. The site has none.

The site sets no cookie and writes no identifier to the browser. Its only browser storage is the learner's own progress, in keys that start with `ro.`, which never leave the device.

## Anonymity in a small cohort

The cohort is small, so a pattern of answers or times could point to a person even without a name. The data are therefore reported as aggregates only. Any item answered fewer than 5 times is left out of anything shared outside the study team. The usage data are not linked to survey responses, and the site does not ask for a participant code.

## To confirm before submission

## Not built

Linked analytics (`analytics_mode: "linked"`) is not built. It would need IRB-approved consent, a participant code that each resident enters, a secure store, and a data-use agreement.
